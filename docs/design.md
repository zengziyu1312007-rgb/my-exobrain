# 产品设计：一个入口，两条成长线

目标：普通用户下载后能认识自己的需求，做成一件真实任务，并在下次继续使用。初始化的价值由产物和使用反馈判断，不以目录数量衡量。

## 共同核心与场景差异

| 层 | 共同部分 | 生活侧 | 工作侧 |
|---|---|---|---|
| 认识使用者 | 目标、标准、条件、偏好、保存范围 | 本人重视的改变、现实精力 | 职责、交付标准、资料权属 |
| 保存上下文 | 六份入口底稿 | 学习应用、选择、小实验 | 项目、信息、贡献、反馈 |
| 完成任务 | 当前需求与可用产物 | 一份能开始的小安排 | 一份能使用的交付物 |
| 长期积累 | 来源、日期、状态、纠错、复盘 | 本人定义的成长证据 | 能力成长与实际可用方法 |

生活／工作是用户可选的起点，不是身份标签。允许两者兼用或不选，由当前任务决定先用什么；资料的权属和共享范围决定隔离方式。

## 初始化节奏

下载 → 安装完整 Skill → 选择独立记录目录 → 讲一件事 → 确认做好标准与条件 → 约定保存类别 → 生成或补齐底稿 → 完成真实任务 → 用户反馈 → 新会话找回。

已有外脑走映射与补缺，紧急任务先执行。用户只要空白模板就到空白阶段结束，不制造虚构背景。

## 分发和数据分开

公开仓库维护通用能力，安装目录保存技能，个人外脑目录保存使用者的实际记录。更新技能不需要迁移或重写个人记录。初版不依赖向量数据库、模型供应商 API、账号注册或后台进程。

## 怎么判断可用

1. 首次使用不依赖填写长问卷，已有答案不重复问。
2. 文件能准确复述本人确认且获准保存的信息，未知仍未知。
3. 第一份产物符合用户自己定义的标准；反馈单独记录。
4. 新会话能从相关文件找回当前任务与依据，需实际验证。
5. 纠错后使用新有效记录，删除后不从可控摘要找回正文。
6. 工作方向同时留下个人成长与实际贡献，不只留待办。

## 版本演进

v0.1.0 交付 Skill、空白初始化、安装器、模板和可复现验证。后续根据真实使用反馈决定是否增加资料导入、检索或移动入口。任何自动同步、团队连接、定时运行都需要独立设计权限与验证，不通过当前 Skill 暗中开启。
